Questions, answered

What is JeriFlow?

JeriFlow is a proposed project and workflow management SaaS concept by Jerico Studio. This website blueprint demonstrates the intended brand and marketing experience.

Who is JeriFlow designed for?

Freelancers, developers, designers, and small creative teams who want a calm, approachable way to organize work.

Can I sign up today?

Not yet. This is a planning and design prototype. Sign-up, authentication, and payment processing are future development decisions.

Will the website work on mobile?

Yes. The intended production site is mobile-first, keyboard accessible, and responsive across common viewport sizes.

Brand & implementation blueprint

This document has two roles: a visual prototype of the proposed SaaS marketing website, and an explicit implementation specification for a future Codex build. The site shown above is a static interactive design reference, not a functional SaaS application.

Source of truth: Jerico Studio is the parent fictional company; JeriFlow is its flagship fictional product. Preserve this distinction. The founder-inspired name is a creative proposal, not a verified registered company or available trademark/domain.

06 — Asset strategy and integration

Codex should inspect the actual ZIP before using it. Locate Flowly_Brand_Asset_Kit.zip in the user's Downloads folder if accessible. Treat it as a candidate asset source from the earlier Flowly direction, not as automatically approved JeriFlow branding. Reuse compatible generic illustrations/icons only; replace any Flowly wordmarks, logos, and named mockups with original JeriFlow/Jerico Studio assets. Preserve the original archive. If inaccessible, ask for the path rather than pretending the assets were found.

  • Use Lucide for interface icons (24px grid, 1.75–2px stroke); keep license notices when redistributing assets.
  • Create original SVG logo and favicon using a stylized J / connected-work motif; no copied Notion logo.
  • Create friendly editorial-style illustrations: outlined faces, paper, cursor, spark, checkmark, planning board; restrained blue/orange/lavender palette.
  • Prefer locally stored SVG and optimized WebP/AVIF for screenshots; use next/image where appropriate.
  • No unlicensed customer logos, fabricated endorsements, or third-party brand marks.

08 — Build instructions for future Codex master prompt

  1. Inspect repository and package manager before changing anything; do not overwrite existing user work.
  2. Read this HTML artifact and use its colors, typography, layout and copy as primary design requirements.
  3. Inspect the downloaded asset archive when permitted; audit names, licenses, file types, and actual usefulness; migrate only suitable assets.
  4. Build with Next.js App Router, TypeScript, Tailwind CSS, lucide-react, and responsive accessible components.
  5. Implement all seven marketing routes; keep product functionality explicitly a demonstration.
  6. Use shared content/data definitions, meaningful navigation, polished empty/error states, and original visual assets.
  7. Run lint, typecheck, and production build; inspect responsive layouts at 390/768/1440px if browser tooling exists.
  8. Report what was implemented, what was tested, what remains a concept, and any unavailable asset paths or blockers.

09 — Research rationale and inspiration

The information architecture draws from established workspace SaaS patterns: connected project boards, docs, and workflow context, while the visual direction draws from minimalist editorial SaaS design. Reference material: Notion Projects, Notion Wikis, and Lucide licensing. These are research references, not sources of copied graphics or copy.

10 — Open decisions before implementation

  • Verify Jerico Studio / JeriFlow name availability and domain/trademark status before public launch.
  • Choose real email/contact endpoint and actual CTA behavior; example addresses in this artifact are nonfunctional placeholders.
  • Approve any final pricing model before showing plans as live offers.
  • Decide whether to build a real SaaS application in a later phase; this blueprint intentionally covers the marketing site first.
Codex handoff rule: The final master prompt should explicitly distinguish this brand specification from implementation. Do not blindly deploy this standalone HTML as the production Next.js site; recreate it as maintainable components and routes.
